# 自动扩充循环

无人值守地一轮一轮扩充案例库：选题 → 写中文案例 → 写英文对照版 → 机器检查 → 独立审计与修改 → 推送到 `main`。

## 怎么运行
- 由 claude.ai 上的一个**定时任务**驱动（北京时间每天 08:35、12:35）：定时任务唤醒常驻的调度会话，调度会话每轮新建一个附带本仓库、可推送 main 的 Opus 执行会话，读 `loop/ROUND.md` 执行一轮。与本地电脑是否开机无关。
- 默认每轮 8 个案例（服装、家纺、原料辅料按 3/3/2 轮换，长期 1:1:1；不再新增体系类），事故 3 / 门禁 2 / 持续改进 3。
- 参数在 `loop/config.json`：每轮案例数、类型配比、总轮数上限 `maxRounds`（默认 10 轮）等。改完推送，下一轮生效。

## 怎么停
- **暂停**：在仓库根目录新建 `LOOP_STOP` 文件并推送。下一轮读到就直接结束，不做任何修改。删除该文件即恢复。
- **永久停止**：在 claude.ai 的定时任务列表中停用或删除该任务；或者跑满 `maxRounds` 后循环自动停用。

## 每轮留下什么
- 新案例：`cases/<前缀>/<ID>_<短名>/`，状态一律 `draft`；英文条目在 `site/cases-en.js`。
- 审计报告与处理结果：`audits/AUDIT-<日期>-loop<轮次>.md` 及 `-response.md`（复审为 `-r2.md`）。
- 进度：`loop/state.json`；每轮记录：`loop/log.md`；`CHANGELOG.md` 的“未发布”部分。
- 每轮一个提交（另有一个加锁的 start 提交），可以按提交回退。

## 边界
- 审计员是与作者同一模型的独立子代理，不等于 GOV-01 的评审。新案例不会被自动批准，`approved` 需要指定评审人签核。
- 不新增或修改法规条目；新增标准的 `verifiedAt` 一律为空；不修改已有案例、治理文件、模板、SOP 与校验脚本。
- 审计后仍有未解决 Critical/Major 的案例会从该轮删除，不会推送。
