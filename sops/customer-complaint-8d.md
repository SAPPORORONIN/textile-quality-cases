# 客户投诉与 8D 关闭标准作业程序

> **Customer Complaint & 8D Closure SOP**

---

## 一、 目的与适用范围

### 1.1 目的

规范从客户投诉/退货信号接收到 8D 关闭的全流程，确保：
- 每一条客户投诉都被记录、分类、响应
- 根因分析严谨，纠正措施可验证
- 闭环时限可控，重复问题被系统性消除
- 索赔回收有据可依

### 1.2 适用范围

- 品牌零售客户投诉（电商退货备注、客服工单、社交媒体投诉）
- B2B 客户质量投诉（零售商/批发商的质量扣款通知、不合格通知）
- 品牌内部质量发现（DQA 终检拒批、IQC 拒收、仓库发现）

- [SYS-011](case:SYS-011) — 8D 关闭 SLA 案例

- [PB-FMEA](doc:PB-FMEA) — FMEA 方法论

## 二、 投诉接收与登记

### 2.1 信号来源与汇集

| 来源 | 接收人 | 汇集方式 |
| :--- | :--- | :--- |
| 电商退货备注 | 客服团队 | 客服系统自动标记含质量关键词的退货 |
| 客服工单（电话/邮件/Chat） | 客服团队 | 含质量问题描述的工单转 QA |
| 社交媒体投诉 | 公关/社交媒体团队 | 含产品质量、安全关键词的帖子转 QA |
| 零售商质量扣款通知 | 采购/财务 | 转 QA |
| DQA 终检拒批 | QA 驻厂 | 检验系统自动创建 8D |
| IQC 来料拒收 | QA IQC | 参考 [SOP-IQC](doc:SOP-IQC) 的不合格处理 |

### 2.2 登记内容

每条投诉在质量管理系统中登记以下信息：
- **投诉编号**（系统自动生成）
- **投诉日期**
- **产品信息**：SKU、PO、批次号（如可追溯）、供应商/工厂
- **问题描述**：缺陷类型、严重程度、数量/比例
- **证据**：照片、测试报告、客户邮件
- **客户/渠道信息**：投诉来源、客户名称
- **初步分类**：缺陷类型（按 taxonomy.json 中的 failureModes 分类）

## 三、 投诉分级与响应时限

### 3.1 严重度分级

| 严重度 | 定义 | 8D 时限 | 升级条件 |
| :--- | :--- | :--- | :--- |
| **Critical** | 安全风险、法规违规、消费者伤害 | **14 自然天** | 7 天未有 D4 → 升级 VP |
| **Major** | 功能缺陷、严重外观缺陷、客户批量退货 | **30 自然天** | 15 天未有 D4 → 升级总监 |
| **Minor** | 轻微外观瑕疵、个别退货 | **60 自然天** | 30 天未有 D4 → 升级经理 |

参考 [SYS-011](case:SYS-011) 的 SLA 体系。

### 3.2 自动升级机制

- **D4（临时围堵措施）未在时限 50% 内完成** → 系统自动发送升级邮件给上级
- **D8（关闭）未在时限内完成** → 系统标记超期，纳入月度质量评审
- **连续 2 个 8D 超期的供应商** → 触发供应商质量等级降级评审

## 四、 8D 流程步骤

### D0 — 问题察觉（投诉登记）

上文第二节的投诉登记即为 D0。

### D1 — 组建团队

| 角色 | 职责 |
| :--- | :--- |
| **8D 负责人**（QA 工程师） | 主导调查、协调供应商、按时限推进 |
| **供应商质量联络人** | 工厂端的根因调查与纠正执行 |
| **技术支持**（如需） | 实验室测试、工艺分析 |

Critical 级别的 8D 由 QA 经理亲自担任负责人或每日跟进。

### D2 — 问题描述

用 5W2H 描述问题：
- **What**：什么缺陷？
- **Where**：哪个部位/位置？
- **When**：什么时候发现？影响哪些批次？
- **Who**：谁发现的？谁的产品？
- **Why（表面）**：初步判断（不是根因，只是描述可见现象）
- **How much**：影响数量、比例、金额
- **How（发现方式）**：终检、来料检、消费者退货、客户投诉

### D3 — 临时围堵措施（Containment）

在根因确定前，先控制影响范围：
- **在制品**：通知工厂停线检查 / 100% 筛选
- **在库成品**：WMS 锁定可疑批次，100% 复检或抽检加严
- **在途**：通知仓库收到后隔离检查
- **已售出**：评估是否需要启动召回程序（参考 [SOP-RCL](doc:SOP-RCL)）

围堵措施必须在 **48 小时内**到位并确认有效。

### D4 — 根因分析

使用 [PB-RCA](doc:PB-RCA) 中的方法：
- **5-Why**：从直接原因逐层追问"为什么"，直到系统原因
- **鱼骨图**：从人、机、料、法、环、测六个维度展开
- **验证**：根因必须能解释"为什么缺陷发生在这里而不是其他地方"和"为什么以前没有发生 / 为什么现在才发生"

**常见误区**：
- 把"操作员不注意"当根因 → 应追问"为什么不注意？是没有培训、没有作业指导书、还是作业条件不允许？"
- 把"供应商面料有问题"当根因 → 应追问"来料检验为什么没有拦截？是没有检还是检了没发现？"

### D5 — 纠正措施制定

针对根因，制定永久纠正措施（不是临时围堵）：
- 每条措施有**责任人、完成日期、验证方法**
- 措施分为：工艺改善、检验加严、规格修订、供应商管理、培训等
- 如根因涉及设计，更新 FMEA（参考 [PB-FMEA](doc:PB-FMEA)）

### D6 — 纠正措施实施与验证

- 供应商提交纠正措施的实施证据（照片、修订后的作业指导书、试产检测数据等）
- QA 验证：下一批来料/出货时重点检查纠正效果
- 对连续型指标，用 SPC 控制图（参考 [PB-SPC](doc:PB-SPC)）验证改善前后的过程变化

### D7 — 预防再发

- 横向展开：同一根因是否可能影响其他产品/供应商？
- 系统改善：是否需要更新 SOP、检验标准、或供应商要求？
- 知识沉淀：根因与解决方案写入案例库，作为今后 FMEA 和培训的输入

### D8 — 关闭与庆贺

- QA 经理审核 D1–D7 完整性，确认关闭
- Critical 级别的 8D 需要 QA 总监签核
- 关闭标准：纠正措施已实施 + 已验证有效 + 无再发迹象（至少观察 2–3 批）

## 五、 索赔回收

### 5.1 索赔依据

| 费用类型 | 计算方式 | 支持文件 |
| :--- | :--- | :--- |
| 不良品成本 | 缺陷件数 × 单价 | 检验报告 + 不合格数量记录 |
| 返工成本 | 返工工时 × 工时单价 | 返工记录 |
| 检验成本 | 加严检验的额外人工 + 测试费 | 检验记录 + 实验室发票 |
| 运费 | 退货 / 换货 / 加急空运运费 | 物流单据 |
| 客户扣款 | 零售商的质量扣款金额 | 扣款通知 |
| 消费者退款 | 电商退款总额 | 退款记录 |

### 5.2 索赔流程

1. 8D 关闭后，QA 汇总损失金额与支持文件
2. 采购/财务向供应商发出索赔通知（Debit Note）
3. 供应商确认或协商
4. 索赔金额从后续货款中扣除或单独结算
5. 索赔回收率纳入月度质量指标（参考 [SYS-011](case:SYS-011) 的索赔回收率从 28% 提升至 61%）

## 六、 重复问题管理

### 6.1 重复问题定义

同一供应商 × 同一失效模式在 **12 个月内**再次发生 8D。

### 6.2 重复问题处理

| 重复次数 | 行动 |
| :--- | :--- |
| **第 2 次** | 8D 升级为 Critical 处理（无论本次严重度），QA 经理主导复盘前次 8D 的纠正措施有效性 |
| **第 3 次** | 供应商质量等级降至"观察"，高管层面约谈供应商负责人 |
| **≥ 4 次** | 启动供应商淘汰评估 |

参考 [SYS-011](case:SYS-011) 的重复问题率从 34% 降至 12% 的实践。

## 七、 月度与季度评审

### 7.1 月度质量评审

| 指标 | 数据来源 | 责任人 |
| :--- | :--- | :--- |
| 8D 开案数 / 关闭数 / 超期数 | 质量管理系统 | QA 经理 |
| 8D 关闭周期中位数（按严重度） | 质量管理系统 | QA 经理 |
| 重复问题率（滚动 12 个月） | 质量管理系统 | QA 经理 |
| 索赔回收率 | 财务系统 | 采购/财务 |
| Top 5 失效模式 Pareto | 质量管理系统 | QA 工程师 |

### 7.2 季度供应商质量评审

- 8D 表现纳入供应商记分卡，与 AQL 检验等级联动（参考 [SYS-009](case:SYS-009)）
- 重复问题供应商列入观察名单并制定专项改善计划
