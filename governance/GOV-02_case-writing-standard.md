# 案例编写标准

## 1. 文件结构
每个案例是一个目录：`cases/<前缀>/<ID>_<slug>/`

| 文件 | 内容 | 维护方式 |
| :--- | :--- | :--- |
| `case.json` | 结构化事实：分类、订单、指标、损失台账、处置、标准/法规引用、评审状态、来源属性 | 手工维护，是数字的**唯一来源** |
| `case.md` | 叙述：背景、过程、机理、措施、STAR | 手工维护，数字必须与 `case.json` 一致 |
| `review-YYYYMMDD.md` | 评审记录（可选，approved 时必需） | 按 `templates/review-record.md` |

- ID 规则：`APP-` 服装、`HT-` 家纺、`RM-` 原料与辅料、`SYS-` 体系；三位流水号，**永不复用**。退役案例保留 ID，状态改为 `retired`。
- 案例标题不加“经典”“重大”“卓越”等修饰词，不出现真实品牌名。

## 2. 必备内容（按案例类型）
校验器按 `registry/taxonomy.json` 的 `requiredMarkers` 检查叙述中是否出现以下章节关键词：

| 类型 | 必备章节 | 必备结构化字段 |
| :--- | :--- | :--- |
| `incident` 质量事故 | 背景、根因、处置、验证、STAR | `metrics`、`ledger`、`disposition` |
| `gate` 产前门禁 | 背景、根因、验证、门禁、STAR | `metrics` |
| `ci` 持续改进 | 背景、根因、验证、STAR | `metrics` |
| `system` 体系建设 | 背景、STAR | `metrics` |

模板见 `templates/case-incident/` 与 `templates/case-short/`。

## 3. 写作规则

### 3.1 要求的来源必须写清楚
每个判定值都要标明属于哪一类：**联邦/州法规**（引用注册表 ID）、**客户/零售商要求**、**行业惯例**、**内部目标**。禁止写“美标限值”“美标要求”这类模糊表述。

### 3.2 方法引用
- 只能引用 `registry/standards.json` 中存在的方法；`status: withdrawn` 或 `kind: terminology` 的条目不能作为验收方法（可以在“历史说明”中提及）。
- 方法名后写清条件：洗涤次数、试样方向与部位、光源、计数规则。

### 3.3 数字
- 所有出现在 `case.json.metrics` 中的前后值，必须在叙述中以同样的数值出现（校验器检查）。
- 金额注明口径：FOB、实际支出或净损失。损失台账各项之和必须等于合计（容差 1%）。
- 比率写明分子分母；小样本写出人数（如 5/12），不写无法由样本得到的百分比。
- 退货率按 [GOV-03](doc:GOV-03) 区分“总退货率”与“质量原因退货率”。
- Cpk 只用于 `registry/metrics.json` 中 `cpkAllowed: true` 的连续型指标，并写明子组数与 MSA 结果。

### 3.4 处置与损失（质量事故必写）
- 写清每一部分货物（在库、在途、在制、面辅料）的决策：放行、返工、回修、转用、降级、退回、拒收、回收、报废、监管下整改、重新设计；
- 写清**为什么不能返修**（如交联损伤、氧化降解不可逆），避免“改了工艺，原来的货就好了”；
- 写清损失由谁承担、依据是什么（合同、责任比例）。

### 3.5 时间线
写出关键节点的大致时间（如“约 7 周后放行”“重新织造约 10 周”），时间要与工序周期匹配，不写“两周内完成所有攻坚”。

### 3.6 措辞
`registry/editorial-rules.json` 中的禁用表述会被校验器拦截，例如“零投诉”“100% 合格”“彻底杜绝”“世界级”。结果写成“观察期 × 周内，质量原因退货率 x%”。

### 3.7 STAR
每个案例结尾写 STAR 讲稿，数字只引用本案已有的数字，不增加新数字；Result 同时写清代价（损失、延误）与改进，不只写正面结果。

### 3.8 语言
- 本版（中文版）正文用简体中文书写。标准与法规编号（如 ASTM D3512、16 CFR 1610）、单位、行业通用缩写（FOB、AQL、Cpk、GSM 等）保留原文；中文术语首次出现时可在括号内附英文，便于与英文版对照。
- 英文版的语言要求见英文版 GOV-02 §3.8：全部用英文书写，校验器拒绝汉字与全角标点。本版校验器不做语言检查。
- 英文译文供站点的英文界面与中英对照模式使用（见 [GOV-07](doc:GOV-07) §6）。对照模式按章节编号与段落逐块对齐，因此两版的章节与段落要一一对应：一版增删章节或段落，另一版同步修改。

## 4. 叙述中的引用语法
| 语法 | 作用 |
| :--- | :--- |
| `[文字](case:APP-001)` | 链接到案例 |
| `[文字](doc:GOV-03)` | 链接到治理文件、模板、SOP、参考文档 |
| `{{APP-001.metrics.quality-return-rate.after}}` | 构建时替换为该案例 `case.json` 中的数值（用于面试与参考文档，避免手抄数字） |

校验器会检查所有引用都能解析。
