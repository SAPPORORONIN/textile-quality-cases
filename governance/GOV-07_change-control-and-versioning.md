# 变更控制与版本

## 1. 版本号
- **案例库版本**（`package.json` 的 `version` 与 `CHANGELOG.md`）：
  - 主版本：结构或 schema 变化（如 v1 → v2 的目录与数据模型重构）；
  - 次版本：新增案例、注册表批量更新、治理文件修订；
  - 修订号：文字修正、单条注册表核实。
- **单个案例版本**（`case.json → version`）：数字、结论或法规引用变化升次版本；文字修正升修订号。

## 2. 变更类型与要求
| 变更 | 触发流程 | 记录 |
| :--- | :--- | :--- |
| 新增案例 | GOV-01 全流程 | CHANGELOG |
| 修改已批准案例的数字/结论 | 状态回到 `draft`，重新评审 | CHANGELOG + 评审记录 |
| 注册表条目更新 | 注册表维护人核实后修改，`verifiedAt` 更新 | CHANGELOG |
| 法规变更（新规/修订/废止） | 5 个工作日内更新注册表；构建报告列出引用该条目的案例；30 天内复审 | CHANGELOG + 受影响案例清单 |
| 标准撤销或替代 | 注册表改为 `withdrawn`；校验器会在引用处报错，必须修改案例 | CHANGELOG |
| 治理文件修改 | 库主批准 | CHANGELOG |

## 3. 退役
- 案例过时（法规改变、工艺淘汰）或被更好的案例替代时，状态改为 `retired`，保留文件与 ID，站点默认隐藏；
- 退役原因写入 `review.notes`。

## 4. 生成文件
`dist/` 下的文件由 `npm run build` 生成，不得手工修改；修改源文件后重新构建。

## 5. 历史版本
v1 的内容已全部迁移到 v2 结构，v1 文件与一次性迁移脚本已于 2.0.1 删除。今后历史追溯以版本控制（建议使用 git）与 CHANGELOG 为准。

## 6. 语言版本
- 英文版由本版 2.0.2（案例 2.1.0）翻译而来。两版的 ID、数字、注册表键与校验规则一致。
- 两版作为独立的库维护。一版的事实、数字、结论或法规引用发生变化，应在同一评审周期内同步到另一版；每条 CHANGELOG 记录注明另一版的对应版本。
- 审计报告不翻译，两版各自保留 `audits/` 历史；英文版的审计历史从零开始。
- 本库站点的英文界面与中英对照模式读取 `site/cases-en.js`、`site/docs-en.js`、`site/registry-en.js` 中的英文版内容。这三个文件不由 `npm run build` 生成，英文版更新后要替换；中文版修改后若英文版未同步，对照模式会显示旧译文，或出现只有一侧有内容的章节。
