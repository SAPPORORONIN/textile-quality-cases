# 独立审计

## 1. 定位
独立审计与 [GOV-01](doc:GOV-01) 的评审是两道不同的关口：

| | 评审（GOV-01） | 独立审计（本文） |
| :--- | :--- | :--- |
| 目的 | 决定案例能否批准 | 找出不合理、经不起推敲的地方 |
| 执行者 | 指定的技术/合规评审人 | 审计代理 `case-auditor`，或不参与该案例编写与评审的资深人员 |
| 产出 | 评审记录与结论 | 审计报告（只列发现，不改文件、不代写） |
| 时机 | 每个案例批准前 | 批准前预审；季度抽审；对外发布前全量审计；法规变更后专项审计 |

审计员只负责发现问题；修改由作者完成，并按 GOV-01 重新评审。

## 2. 审计代理
- 定义文件：`.claude/agents/case-auditor.md`
- 角色：资深、严厉、冷静、客观；先运行校验器，只报告机器查不出的问题；每条发现带位置、原文、依据、严重度与置信度；报告前自我反驳以减少误报。
- 权限：只读（读文件、搜索、运行 `npm run validate` / `npm test`、上网核实官方来源）；不得修改文件，不得运行 `npm run build`。
- 调用：在 Claude Code 中运行 `/audit-cases <范围>`，范围可以是案例 ID（如 `APP-001`）、前缀（如 `HT`）或 `all`。报告保存到 `audits/AUDIT-YYYYMMDD-<范围>.md`。

## 3. 严重度
| 严重度 | 定义 | 处理时限 |
| :--- | :--- | :--- |
| Critical | 法规事实或适用错误；或错误足以推翻核心结论 | 案例立即退回 `draft`，修正前不得对外使用 |
| Major | 机理错误、数字矛盾或量级失真、处置不成立、关键验证缺失 | 30 天内修正，修正前不得批准 |
| Minor | 口径、单位、条件不清，轻微不一致 | 下次修订时处理 |
| Observation | 补充后可信度提高 | 作者自行决定 |

## 4. 发现的处理
1. 作者对每条发现给出处理结果：已修正 / 不同意（附理由）/ 需更多信息；
2. 作者与审计意见不一致时，由库主指定第二位资深人员裁定；
3. 同一类问题在多个案例反复出现时，库主评估是否把它写进校验器规则或 GOV-02，让机器以后自动拦截；
4. 审计报告与处理结果保留在 `audits/`，不删除。

## 5. 对审计本身的要求
- 每条发现必须能复核：有位置、原文与依据；
- 不确定的标“需核实”并写明核实方法，不得把印象写成结论；
- 不为凑数报告风格问题，没有问题就写“未发现需要报告的问题”；
- 审计代理的结论同样可能出错。Critical 与 Major 发现在采纳前，由人工抽查依据是否成立。
