# 分类体系与注册表维护

## 1. 注册表一览
| 文件 | 内容 | 维护人 | 校验器如何使用 |
| :--- | :--- | :--- | :--- |
| `registry/taxonomy.json` | 领域、阶段、案例类型、失效模式、专业、工具、处置决策、来源属性、评审状态 | 库主 | 案例字段必须取自这里的枚举值 |
| `registry/standards.json` | 检测方法与标准：机构、编号、状态、类型、核实日期 | 注册表维护人 | 撤销或术语类标准被当作方法引用时报错 |
| `registry/regulations.json` | 法规：辖区、机构、条款、要点、状态、来源、核实日期 | 注册表维护人（合规） | 已废止法规只能作为历史引用；未核实/过期给警告 |
| `registry/metrics.json` | 指标定义：单位、类型、方向、是否允许 Cpk | 库主 | 指标 ID 必须存在；等级型指标禁止 Cpk |
| `registry/editorial-rules.json` | 禁用表述、品牌名单、数字检查级别 | 库主 | 叙述扫描 |

## 2. 分类维度
一个案例同时有以下标签，用于检索与统计：
- **领域** `domain`：服装 / 家纺 / 原料与辅料 / 体系与供应链；
- **阶段** `stage`：问题被发现的环节（产前/开发、产中、出货/到港、售后），不是根因发生的环节；
- **类型** `caseType`：质量事故、产前门禁、持续改进、体系建设；
- **失效模式** `failureModes`（可多选）；
- **专业** `disciplines`（可多选）；
- **工具** `tools`（可多选）。

## 3. 新增枚举值
1. 先确认现有值不能覆盖；
2. 在 taxonomy 中新增，写清中文名与定义；
3. 在 CHANGELOG 记录；
4. 同一概念不允许出现两个 ID（如 `seam-burst` 与 `seam-failure`）。

## 4. 注册表条目新增与核实
- 新增标准/法规时至少填写：编号、标题、类型/状态、来源链接；`verifiedAt` 只有在对照来源核实后才填写；
- 每季度复盘时导出“未核实 / 即将过期”清单（站点“治理健康度”页面直接显示），由维护人逐条处理。
