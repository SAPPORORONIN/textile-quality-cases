# 来源与证据政策

## 1. 来源层级（从高到低）
| 层级 | 来源 | 用途 |
| :---: | :--- | :--- |
| 1 | 法规原文：eCFR、Federal Register、州法原文 | 法规条款的最终依据 |
| 2 | 监管机构官方指南与 FAQ：CPSC、FTC、CBP、OEHHA | 适用范围与执法口径 |
| 3 | 标准组织目录与标准文本：AATCC、ASTM、ISO、NFPA、IDFB | 方法名称、状态（现行/撤销）、方法要点 |
| 4 | 认可实验室技术通报、行业协会资料 | 实务解读，需交叉核对 1–3 |
| 5 | 媒体、博客、供应商宣传 | 只作线索，不得作为唯一依据 |

## 2. 注册表条目要求
- `sources` 至少 1 条层级 1–3 的链接；
- `verifiedAt`：核实人对照来源确认内容的日期；未核实填 `null`，**不得猜测**；
- 法规条目超过 180 天未核实，校验器发出警告；被案例引用的法规条目未核实，在评审时必须先核实；
- 已废止的法规（如原 16 CFR 253 羽绒指南）保留条目并标 `status: rescinded`，只能放在案例的 `historicalRegulations` 中。

## 3. 案例中的事实
| 事实类型 | 证据要求 |
| :--- | :--- |
| 法规/标准事实 | 引用注册表 ID；叙述与注册表不一致时以注册表为准并修正叙述 |
| 材料/工艺机理 | 符合教科书或技术文献的一般认知；有争议的机理写明“推测”并给出验证试验 |
| 数字（示例案例） | 量级须与行业常见水平一致（如住宅割绒地毯簇绒拔出力底线约 3 lbf、服装电商总退货率 15–30%）；评审人对明显不合理的量级有否决权 |
| 数字（真实案例） | 必须有内部证据（测试报告、财务凭证）存档，路径写入评审记录，不放入公开库 |

## 4. 引用格式
- 注册表：`sources` 存 URL；
- 叙述中：写法规编号或标准编号即可（如“16 CFR 1632”“ASTM D7142”），由注册表承载来源链接。

## 5. 不确定时怎么写
写“需按现行版本核实”“以客户手册为准”，而不是给出看似精确但未经核实的数值。
