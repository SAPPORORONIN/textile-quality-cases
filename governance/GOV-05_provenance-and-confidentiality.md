# 数据来源与保密政策

## 1. 案例来源属性（case.json → provenance）
| 值 | 含义 | 要求 |
| :--- | :--- | :--- |
| `illustrative` | 示例案例：情景与数字为教学用途编写 | 数字量级合理、内部一致；站点自动显示“示例案例”提示 |
| `composite` | 合成案例：多个真实经历去标识化后合并改写 | 不得能反推出具体企业、订单、人员；数字已调整 |
| `anonymized-real` | 去标识化真实案例 | 须有信息所有方书面授权；证据存档在库外；评审记录注明授权与证据位置 |

当前全部案例为 `illustrative`。

## 2. 去标识化规则
- 不出现真实零售商、品牌、工厂、实验室、物流公司名称作为事件主体（校验器对 `brandWatchlist` 名单报错）；用“美国大型零售连锁”“第三方实验室”等泛称。
- 不出现可识别的 PO 号、款号、日期组合、人名、城市 + 工厂规模组合。
- 设备与材料可写通用规格（如“65/9 轻圆头针”）；需要品牌型号时写“某品牌 SES 型”，不作为事件主体。
- 真实合同条款、价格、索赔金额不得原样进入公开库。

## 3. 外部发布
- 公开发布（网站、社交媒体、课程资料）前必须确认所有案例为 `illustrative` 或已获授权；
- 发布物须保留“示例案例，不对应真实事件”的声明。

## 4. 个人信息
退货、客服类案例只使用汇总数据，不放入消费者个人信息；如需样例，使用虚构数据。
